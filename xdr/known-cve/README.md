# known-cve 차단 연결

`decide.mjs`는 파일·패키지·외부 요청 없이 경보의 패턴만 판단합니다. 확인용 `read-alerts.mjs`는 판단 파일이 불러오지 않습니다.

`respond.mjs`의 `createResponder`는 `block`·확신도 0.85 이상·유효한 근거 경보 번호·신선한 경보에만 차단 규칙을 만듭니다. 서버가 제공한 `resolveVerifiedRequest(alertId)`로 경보와 엔진 검증 요청을 연결해야 합니다. Wazuh의 계정명·출발 IP를 ZTNA 가명 신원으로 변환하거나 클라이언트 헤더에서 가져오면 안 됩니다. 연결할 수 없으면 `not_bound`로 기록하고 규칙을 만들지 않습니다.

규칙은 사용자·기기·반·프로젝트·서비스·메서드·정확한 경로·쿼리 해시에 한정되며, 경보 시각부터 5분 뒤 만료됩니다. 동일 경보 재처리는 규칙을 중복 생성하거나 만료를 연장하지 않습니다. 오래된 원본 경보를 현재 운영 차단으로 적용하지 않습니다. 알림은 `xdr/alerts.log`에 경보 번호·패턴 이름·확신도·처리 상태·만료만 한 줄씩 추가합니다. 원문·주소·계정·토큰은 기록하지 않습니다. 생성된 규칙과 알림 파일은 Git에서 제외합니다.

`createConnectedDecider({baseDecide, ruleIds, ...})`는 기존 판정기 결과를 먼저 실행하고 유지합니다. 기존 허용 요청 중 유효한 차단 규칙의 정확한 범위와 일치한 경우만 기존 등록 규칙 `zone_access`와 이유 코드 `zone_access_denied`로 거부합니다. 기존 판정기의 규칙 목록·내용과 `decide.mjs`는 수정하지 않았습니다.

운영 엔진에는 제공된 공식 등록 API를 통해 이 어댑터와 서버 상관관계 함수를 연결해야 합니다. 현재 저장소에는 그 운영 등록 계약이 없어 자동 연결을 실행하지 않았습니다. 로컬 파일을 만들었다고 운영 회수를 완료했다고 주장하지 않습니다.

시험 명령:

```sh
node --experimental-vm-modules --test test/known-cve-respond.test.mjs test/known-cve-decide.test.mjs test/known-cve-reader.test.mjs
```

24건 재흐름 시험은 합성 엔진 요청과 시험 시계·임시 파일을 사용합니다. 명확한 패턴만 거부되고 정상 기기 요청·연결되지 않은 경보·애매한 패턴은 차단 규칙을 만들지 않습니다. 만료 뒤에는 기존 정상 판정으로 돌아갑니다. 운영 PC·실제 엔진 차단 실측이 아닙니다.

최종 분류 확인: T1190으로 분류된 불확실한 경보의 맥락은 별도 근거 패턴으로 알림만 남깁니다. 현재 result.json은 block 8 · alert 8 · record 8이며 정상 8건의 block은 0건입니다. 판단 모듈은 여전히 import·입출력·외부 요청이 없습니다.
